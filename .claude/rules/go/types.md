# Go — Types and Data

The decisions behind these are in the `go-types` skill; these apply everywhere.

- **Make the zero value useful, or make it fail loudly.** `sync.Mutex`, `bytes.Buffer` and
  `strings.Builder` work undeclared, and a type that can do the same should. When it cannot — a
  required dependency, an invariant between fields — the fields are unexported, `NewX` is the only
  way to a usable value and returns an error on invalid input, and a method on the zero value
  returns an error rather than half-working.
- **A domain value gets a defined type**: `type OrderID string`, `type Cents int64`. Two IDs that
  share `string` can be swapped at every call site without a compiler error; two defined types
  cannot. **Durations are `time.Duration` and instants are `time.Time`**, never an `int` of seconds.
- **An enum is a defined type with `iota` constants whose zero is invalid or explicitly unknown** —
  `StatusUnknown` first, or `iota + 1`. A zero that means a real state is the state every
  forgotten field silently gets. It has a `String` method, generated by `stringer`.
- **Struct literals always name their fields.** `Transfer{From: a, To: b, Amount: x}`;
  `Transfer{a, b, x}` type-checks with the accounts swapped and moves the money backwards. Vet
  checks this only for types from other packages; the rule covers your own, however few the
  fields — `image.Point{X: 1, Y: 2}`, not `image.Point{1, 2}`.
- **`any` means "stop checking".** It stays at a boundary whose shape is truly unknown, and is
  narrowed on the first line with a type switch or a comma-ok assertion — never passed further,
  never returned from a domain function. **`map[string]any` never crosses a package**: that is a
  struct nobody wrote.
- **A type assertion always takes the comma-ok form** — `v, ok := x.(T)` — outside a `switch`. The
  one-value form panics on the input nobody tested.
- **Pointer or value is decided per type, not per method.** A pointer receiver when any method
  mutates, when the type holds a `sync.Mutex` or anything that must not be copied, or when it is
  large; then every method takes the pointer. Small immutable values — `time.Time`, a `Money` —
  take value receivers throughout.
- **A pointer is not an optional.** `*int` to mean "maybe absent" makes every reader check for
  `nil` and every writer allocate; prefer the zero value, a `(T, bool)` pair, or `sql.Null[T]` at
  a database boundary. A pointer field is right where the wire format distinguishes absent from
  zero.
- **A nil slice is an empty slice.** Declare with `var orders []Order`, test with
  `len(orders) == 0`, and never return `nil` and `[]T{}` with different meanings — the one place
  they differ, JSON, is in `go-json`.
- **Copy at the boundary.** A slice or map received and stored, or a field returned from an
  accessor, aliases the caller's memory: `slices.Clone` and `maps.Clone` on the way in and out of
  anything that keeps state. **Never mutate an argument** unless the function is named and
  documented for it, as `slices.Sort` is.
- **Embed only when every promoted method is meant to be the outer type's API**, never to save
  typing — embed a `sync.Mutex` and every caller can `Lock` your struct. Mutexes, clients and
  loggers are named fields.
- **A literal that is user-facing, used twice, or a magic number is a named constant**
  (`const defaultPageSize = 50`), living with the code that reads it.
- **Generics when the body is identical for every type** — a container, a slice algorithm, a
  result cache. When the behaviour differs per type, that is an interface. The standard library
  first: `slices`, `maps`, `cmp`, `min`, `max`, `iter`.
